# 2D Квадракоптер в XZ плоскости: МРС следование траектории в коридоре с гауссовским ветром
Учебный проект по моделированию и управлению квадрокоптером в двумерной вертикальной плоскости. Проект реализует отслеживание вертикально ориентированной траектории в форме восьмёрки с помощью Model Predictive Control (MPC) в симуляторе MuJoCo. На квадрокоптер действует изменяющаяся нисходящая сила ветра, смоделированная как сглаженный гауссовский случайный процесс.

# Постановка задачи
Рассматривается квадрокоптер, движение которого ограничено вертикальной плоскостью X-Z. Для уменьшения размерности задачи используются три степени свободы:
`x` — горизонтальное перемещение;
`z` — вертикальное перемещение;
`theta` — угол тангажа.

Остальные пространственные степени свободы (y, roll, yaw) в модели не используются. Среда представляет собой вертикальный коридор с полом и двумя боковыми стенами. На аппарат действует переменная сила ветра, направленная вниз.
Цель управления — заставить квадрокоптер отслеживать заданную траекторию:
x_ref(t) = B sin(2ωt)
z_ref(t) = z0 + A sin(ωt)

# Запуск симуляции
Для проекта требуются два терминала, потому что симулятор и MPC-контроллер работают как отдельные процессы и обмениваются данными через ZeroMQ.
## Терминал 1 — контроллер
Из корня репозитория: 
cd examples\quadrotor_drone\control
python controller_server.py

После запуска появится сообщение:
MPC controller started.
Waiting for simulator on tcp://127.0.0.1:5555 ...


## Терминал 2 — симулятор
Из корня репозитория:
cd examples\quadrotor_drone\sim
python simulator.py

Откроется окно MuJoCo. После завершения симуляции журнал будет сохранён в:
examples/quadrotor_drone/results/flight_log.csv

# Построение графиков
После завершения симуляции:
cd ..
python plot_results.py

Будут созданы:
results/trajectory.png
results/tracking_error.png
results/wind.png

Файлы результатов не хранятся в Git-репозитории, поскольку они генерируются заново при каждом запуске симуляции.

# Параметры эксперимента
Основные параметры находятся непосредственно в исходном коде:
- время моделирования — `30 s`;
- шаг симуляции — `0.02 s`;
- масса квадрокоптера — `1 kg`;
- длина плеча — `0.32 m`;
- гравитация — `9.81 m/s²`;
- горизонтальная амплитуда восьмёрки — `0.75 m`;
- вертикальная амплитуда — `1.15 m`;
- период траектории — `10 s`;
- средняя сила ветра — `-0.7 N`;
- стандартное отклонение ветровой составляющей — `0.30 N`.

# Тесты

Локальный запуск:
pytest

Тесты проверяют:
- наличие основных файлов проекта;
- воспроизводимость модели ветра при одинаковом seed;
- направление среднего воздействия ветра;
- форму и основные точки вертикальной траектории-восьмёрки;
- размерность MPC reference trajectory.

# Continuous Integration
В репозитории настроен GitHub Actions workflow. При push и pull request выполняются установка зависимостей и автоматические тесты. CI использует фиксированную версию Python и отдельные development-зависимости. Это позволяет автоматически проверять, что изменения не ломают базовую структуру проекта.

# Результат работы
В результате работы квадрокоптер в симуляции должен отслеживать заданную траекторию в вертикальной плоскости XZ, несмотря на воздействие изменяющегося ветра. Полученные данные позволяют оценить качество работы регулятора по ошибке отслеживания траектории. По пути examples/quadrotor_drone/results можно найти результаты выполнения программы в качестве графиков и таблицы с данными.
